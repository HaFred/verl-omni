# Bagel Co-RL (Joint-Training) (RFC 453) — GPU run guide for agents

Multi-turn agentic Co-RL (Joint-Training) on one Bagel-7B-MoT actor: the UND text path is the
Hermes tool-calling agent, the GEN path (`*_moe_gen`) is its own `generate_image`
tool, both trained in one composite optimizer step (UND token GRPO + GEN
FlowGRPO). Design: RFC [#453](https://github.com/verl-project/verl-omni/issues/453)
(v3 refactor + implementation plan on the fork under `outputs/`).

**Fail-closed rules — do not violate:**

- UND must be the published Bagel checkpoint emitting Hermes `<tool_call>`. If
  dual-role serving cannot be proven, STOP — never fall back to a Qwen actor or a
  Qwen image sidecar.
- Never edit Mode (2a) `examples/agenticllmgrpo_trainer/agent_llm/run_agenticrpco_grpo_lora.sh`.
- No mid-episode weight sync, no update before the N-sibling gather completes.

## Glossary (do not conflate)

| Symbol | Meaning |
| --- | --- |
| `J` | UND policy turns inside one episode (`J >= K`) |
| `K` | `generate_image` calls inside the same episode (spike default caps `K` at 1) |
| `S` | FlowGRPO seeds per `generate_image` call (`agent.gen_samples_per_call`, must be >= 2) |
| `N` | Sibling episodes per dataset task for token GRPO (`rollout.n`) |

Episode patterns the stack must accept: paired (`J == K`), mixed (`J > K >= 1`,
reflection-only turns), gen-off (`K = 0`, UND-only). Metric glossary:
`und/no_image_credit` counts `K = 0` episodes only; `gen/dropped_incomplete_groups`
counts calls whose valid seeds != `S`.

## 4. e2e training — `run_agentic_bagel_rpco_lora.sh`

```bash
# 4-GPU default (CUDA_VISIBLE_DEVICES defaults to 2,3,4,5 on the author's boxes):
bash examples/agenticllmgrpo_trainer/bagel/run_agentic_bagel_rpco_lora.sh

# 1-GPU sanity (RM off by default — actor+Omni+RM cannot fit one card):
CUDA_VISIBLE_DEVICES=3 bash examples/agenticllmgrpo_trainer/bagel/run_agentic_bagel_rpco_lora.sh
```

Ladder: run 1-GPU first (loop + composite step, RM off), then 2-GPU, then the
4-GPU acceptance run with `ENABLE_RM=1` (colocated Qwen RM, TP-sharded across the
pool). `BAGEL_UND_AR_SERVING_READY=1` is the recipe default — flip to `0` to
re-hear the fail-closed gate after any serving change.

**Acceptance checklist (record all of it for the PR body):**

- ≥3 composite optimizer steps complete; `und_batch` nonempty every step;
  `gen/skipped_no_groups < 1` on steps with complete groups.
- Validation batch contains pattern-1, pattern-2 and pattern-3 episodes; at least
  one pattern-2 episode shows the RM-cued arc rewrite → `good_enough=YES` → `Done.`
  (requires `ENABLE_RM=1`).
- `und/no_image_credit` == count of `K=0` episodes; `gen/dropped_incomplete_groups`
  == 0 when all `S` seeds succeed; a `K=2` episode yields `2*S` GEN rows.
- One `policy_version` per step on BOTH replicas (UND AR + GEN diffusion); no
  mid-episode sync events in the logs.
- `bagel_role_timing` (`und_decode_s` / `gen_s` / `rm_s`) present per episode —
  this is the serial-baseline KPI anchor; do not claim throughput gains without it.
- Reward-hacking watch (latent-KL is the interim regularizer): validation reward
  inverting after initial rise, texture artifacts → report immediately, do not
  tune through it.

| `AGENT_WORKERS` | `8` | Agent-loop workers; pinned into `rollout.agent.num_workers` because `PEC_SIZE` is sized from it |
| `PEC_SIZE` | `S * N * AGENT_WORKERS` (floor 32) | LRU entries in the conditioning cache. Sized against the live working set, not the 32 default: one entry is live per in-flight S-group per worker, so `N=8, S=4, 8 workers` needs 256 or a group's own entry is evicted before the group finishes |
| `MAX_PROMPT_LEN` | `1024` (512 on a 1/2-GPU pool) | Pins **both** `data.max_prompt_length`/`max_response_length` **and** `actor_rollout_ref.rollout.prompt_length`/`response_length`. The pairs must agree (`validate_bagel_corl_config` rejects a mismatch): the data pair sizes the dataset and the UND AR engine's `max_model_len`, while the rollout pair is the shape every trajectory is padded to *and* the budget `run_serial_episode` stops the UND loop at. `_pad_token_ids` does not truncate, so a mismatch hands back an over-long tensor instead of trimming it |
| `MAX_UND_TURNS` | `8` | Episode UND turn cap. In practice bounded by `2 x MAX_PROMPT_LEN`: `_und_decode` passes `prompt_ids + response_ids`, so the loop stops as soon as that sum reaches `rollout.prompt_length + rollout.response_length` — otherwise it would ask the engine for a decode with no room for a token |
| `REBUILD_UNICOT` | `1` | Rebuild train/val parquet before launch |
| `ROLLOUT_TEMPERATURE` / `ROLLOUT_TOP_P` / `ROLLOUT_TOP_K` / `ROLLOUT_REPETITION_PENALTY` | `0.7` / `0.9` / `50` / `1.05` | UND AR sampling for the Hermes tool-call decode. These intentionally mirror `bagel_corl_deploy_ar.yaml:default_sampling_params`; the agent loop sends all four keys explicitly, so leaving them unset does **not** fall back to those defaults — it overrides them with the rollout defaults, where the checkpoint emits one role label until the response budget is spent (no tool call, no GEN, no reward). See the repetition-loop row in §5. `repetition_penalty` is honored only because `rollout.repetition_penalty` now exists in `rollout.yaml` and the agent loops read it; they used to hardcode `1.0` and silently discard the knob |
| `RUN_TS` / `RUN_NAME` / `RUN_DIR` | `date +%Y%m%d_%H%M%S` / `bagel_corl_$RUN_TS` / `outputs/$RUN_NAME` | The Hydra run dir, passed as `hydra.run.dir`. Default `outputs/<date>/<time>` is flattened to one self-describing folder per run, `outputs/bagel_corl_YYYYMMDD_hhmmss` (the sibling e2e recipe's `outputs/e2e/agentic_rpco_<ts>` convention). It holds `.hydra/` (composed config + overrides) and `main_omni.log`. Hydra refuses a run dir that already exists, so to re-enter a folder either pass the original stamp (`RUN_TS=20260921_135849 …`) or point `RUN_DIR` at it. The override is `hydra.run.dir`, **not** a `job.chdir`: Hydra 1.3 leaves `hydra.job.chdir: null` (off), so the relative deploy-config paths (`examples/agenticllmgrpo_trainer/bagel/bagel_corl_deploy_tp2.yaml`) still resolve against the repo root |
| `DEFAULT_LOCAL_DIR` | unset | Empty keeps the config's `checkpoints/${project_name}/${experiment_name}` = `checkpoints/bagel_corl/bagel_corl_pr1`, which **every** run that leaves `EXPERIMENT_NAME` alone shares. Set it (e.g. `DEFAULT_LOCAL_DIR=$RUN_DIR/checkpoints`) to stamp the checkpoints per run and make the run self-contained. The rollout dumps stay under `outputs/e2e/<experiment_name>/` in either case — see `BAGEL_CORL_TRACE_DUMP` |
| `BAGEL_CORL_TRACE_DUMP` | `1` | Per-episode trajectory dump for the Co-RL UND lane, at `<e2e_root>/<experiment_name>/rollout_trajectories/step_XXXXXX/sample_*.{json,txt}` (`bagel_corl.dump_episode_trace`). `0` opts out. The dump root is bound from `trainer.experiment_name`, **not** from the Hydra run dir above, so this recipe lands in `outputs/e2e/bagel_corl_pr1/` |

Training-side knobs (in the launch command, RFC §4.4/§5): `actor.optim.lr` (UND),
`+actor_rollout_ref.model.lr_gen=3e-5` (GEN group), `loss_weight_und/gen`,
`loss_mode` (`flow_grpo`; `grpo_guard` = GRPO-Guard ratio normalization,

### R2 — GEN conditioning reuse (RFC §4.4.2, §4.4.4)

`generate_image` submits `S` seeds that share one conditioning, and each seed
otherwise re-encodes it. R2 amortizes that: one encode serves the whole group.

Three things have to line up or the cache is on and buys nothing:

1. **The knobs are a pair.** `enable_prompt_embed_cache=True` turns the cache on;
   `enable_prompt_embed_cache_routing_affinity=True` pins one whole S-group to
   one replica. Each replica owns its own cache and the client acquires its
   replica from the load balancer using the request id, so *without* the pin
   seeds 2..S scatter across workers holding no entry. Both come from
   `ENABLE_PEC=1`.
   All three R2 knobs must be passed to Hydra as **`+key=value`** (append), not as
   plain overrides. These recipes compose against `omni_trainer`, whose
   `actor_rollout_ref.rollout` node is typed `verl.workers.config.RolloutConfig`;
   the fields live on `DiffusionRolloutConfig` and are only grafted on at run time
   by `_rewrite_bagel_corl_configs`. A bare override therefore aborts the launch
   with `Could not override 'actor_rollout_ref.rollout.enable_prompt_embed_cache'`,
   which is how this shipped broken the first time.
2. **`prompt_embed_cache_size` covers the live working set**, hence the
   `S * N * AGENT_WORKERS` default — see the knob table above. Too small and a
   group evicts its own entry mid-group, which reads exactly like "the cache
   never hits".
3. **The identity is derived, never hand-set.** `cond_uid` is a SHA-256 over the
   conditioning token ids the GEN stage actually encodes, and `cond_len` its
   length. Both ride each GEN TQ row; the UND row carries the *distinct*
   `gen_cond_uids` for the episode (§4.4.2a).

The per-step metrics are **measured from the engine's own cache counters**, not
modelled client-side (§4.4.4), and are omitted entirely — never fabricated as
`0.0` — when the engine exposes none:

| Metric | Definition | Target |
| --- | --- | --- |
| `gen/cond_recompute_ratio` | conditioning prefills / `generate_image` calls. Prefills are cache **misses + bypasses**; a bypass always encoded | `1/S` |
| `gen/prompt_embed_cache_hit_rate` | hits / (hits + misses). Bypasses are excluded — they are not cache decisions | `1 - 1/S` |
| `gen/cond_amortization` | `1 / cond_recompute_ratio` — "one encode serves this many calls" | `S` |

Counts (`gen/cond_cache_hits|misses|bypassed`) are summed over the batch; the
three ratios above are batch means of per-episode values. An episode whose probe
never answered publishes **no** R2 keys — never a `0.0`, which would be the best
possible score and would make the §8.7 gate pass on a run that reused nothing.

Where each half of R2 lives, so it can be checked after a change:

| Hop | Site |
| --- | --- |
| The knobs exist on the rollout config | `verl_omni/workers/config/diffusion/rollout.py` (`enable_prompt_embed_cache`, `prompt_embed_cache_size`, `enable_prompt_embed_cache_routing_affinity`) |
| Config reaches the engine | `vllm_omni_diffusion_strategy.prepare_engine_args` → `engine_args["enable_prompt_embed_cache" / "prompt_embed_cache_size"]` (covered by `test_diffusion_strategy_preserves_engine_argument_preparation`) |
| Counters are read back | `vllm_omni_async_server.prompt_embed_cache_stats` → `DiffusionModelRunner.get_prompt_embed_cache_stats` → `PromptEmbedCache.stats()` |
| Affinity is applied | `BagelMultiturnAgentLoop._generate_image` reuses one request id for the S-group; `BagelDualRoleLLMServerClient.prompt_embed_cache_stats` re-acquires that same replica |
| Identity | `conditioning_uid` / `cond_len` on every GEN row; distinct `gen_cond_uids` on the UND row |
| **Invalidated at weight publish** | `VLLMOmniHttpServer._invalidate_policy_caches` (RFC §4.4.0(b)) — clears the LoRA request cache **and** the engine's conditioning cache on `set_global_steps` / `sleep` / `wake_up` / `release_kv_cache` / `resume_kv_cache` |

The invalidation is not optional. A conditioning entry is a function of
`(tokens, weights)`, and §4.11 publishes new merged weights every composite step:
serving an entry computed under `policy_version = v-1` would condition on a
*different policy* than the one being trained, silently mixing policies
mid-episode and biasing the importance ratio. The entries are exact *within* a
weight version, which is why the rule is "flush on publish" rather than "leave
the cache off".

Note that `vllm_omni` also honours `OMNI_DIFFUSION_PROMPT_EMBED_CACHE` /
`..._SIZE` **as an override of the config** inside the worker process — useful if
a deploy plumbing change ever stops carrying the two config keys, and the quickest
way to bisect "recipe says on, engine says off".
